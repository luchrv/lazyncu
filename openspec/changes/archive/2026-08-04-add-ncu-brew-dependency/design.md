# Design: add-ncu-brew-dependency

## Context

See proposal.md — Why. Current state:

- `.goreleaser.yaml` `homebrew_casks` entry declares no `dependencies`; the generated `Casks/lazyncu.rb` in `luchrv/homebrew-tap` therefore has no `depends_on` stanza.
- GoReleaser's cask config supports `dependencies: [{formula: <name>} | {cask: <name>}]` (`pkg/config/config.go` `HomebrewCaskDependency`), and its cask template emits the corresponding `depends_on` stanza. CI uses `goreleaser-action@v6` with `version: "~> v2"` (latest v2), so the feature is available at release time.
- homebrew-core ships the `npm-check-updates` formula (23.0.0 at time of writing; lazyncu's preflight requires >= 18). The formula depends on `node`, which brew installs transitively.
- The cask is regenerated on every tag push; nothing is edited by hand in the tap.

## Goals / Non-Goals

**Goals:**
- `brew install luchrv/tap/lazyncu` yields a working install with `ncu` on PATH, no manual step.
- README accurately reflects the per-channel requirements.

**Non-Goals:**
- No runtime fallback (`npx`) or auto-install in the app — rejected in exploration (read-only invariant).
- No changes to the preflight check, its error message, or any Go code.
- No manual edits to the tap repository.

## Decisions

**D1 — Declare the dependency in `.goreleaser.yaml`, not in the tap.**
The cask file is generated (`# This file was generated by GoReleaser. DO NOT EDIT.`); a hand edit would be overwritten on the next release. The config is the single source of truth:

```yaml
homebrew_casks:
  - name: lazyncu
    dependencies:
      - formula: npm-check-updates
```

Alternative considered: patching `Casks/lazyncu.rb` directly for immediate effect — rejected, would drift and be clobbered.

**D2 — Depend on the homebrew-core `npm-check-updates` formula, not on `node` + caveat.**
The formula pins the actual runtime need (the `ncu` binary) and satisfies the version floor (23 >= 18). Depending on `node` alone would still require a manual `npm install -g` step.

**D3 — README wording: brew channel includes ncu; other channels keep the manual prerequisite.**
The Requirements section keeps the `npm install -g npm-check-updates` instruction but scopes it to release-binary / `go install` / source installs; the Install section notes brew handles it automatically.

## Risks / Trade-offs

- [Brew installs its own `node` for nvm/fnm users] → Harmless duplicate; PATH order is unaffected for their projects. Accepted, noted in proposal.
- [User already has ncu via `npm -g`; brew adds a second copy] → PATH order decides which runs; both satisfy >= 18. Accepted.
- [Cask `depends_on formula:` requires a recent Homebrew] → Long-standing cask stanza, supported for years. No mitigation needed.
- [Change is invisible until next release] → Expected; verify via snapshot build (`goreleaser release --snapshot --clean`) that the generated cask contains `depends_on formula: "npm-check-updates"` before tagging.

## Migration Plan

1. Merge config + README change.
2. Next tagged release regenerates `Casks/lazyncu.rb` with the `depends_on` stanza.
3. Existing brew users pick it up on `brew upgrade` (brew installs missing dependencies of the new cask version).
4. Rollback: remove the `dependencies` block and cut another release.
